# Ticket 10 candidate preview policy (mock-only)

The selected invited candidate can be a **controlled-join candidate**, not a deliverable account. A complete, fresh negative first-usage-record lookup in the typed mock evidence is `unobserved_prejoin`, not `never_used` and not a zero measurement. Even a legacy candidate `never_used` assertion cannot qualify **without the same independent complete-negative lookup**. It is scoped to the selected canonical Workspace, exact account/identifier, mother session generation, current verification and selected account/credential/membership revisions. The lookup must explicitly report `complete` and `absent`, with its own mock ledger source/evidence ID. Its ID is a domain-separated SHA-256 digest of the full canonical proof excluding the ID itself (including source, scope, revisions, completeness, result and UTC observation/expiry times); reuse of that ID with changed content fails closed. Missing, stale, partial, wrong-scope or failed probes remain unknown/excluded. Known ever-used history in retained mock previews (across Workspaces), global delivery/reservation/pending/suspected protection, unknown protection, wrong invitation/seat type and duplicate member identity block eligibility. Owner mapping is explicit and seat-type matched.

An eligible candidate is labeled `join_candidate_pending_first_probe` for delivery: **not deliverable**. Neither an invitation nor Personal account probe establishes target Workspace usage. No join or delivery executor, post-join scoped probe/zero ledger or durable cross-writer fence exists in this slice. The `deliverable` status is not emitted by Ticket 10. New frozen preview facts carry `policyVersion: 1` in their digest. Missing or older policy versions are served as `needs_verification` with candidates blocked even if a prior `ready` preview already said `deliveryStatus=join_candidate_pending_first_probe`: that status alone never proves the complete-negative lookup. Legacy facts without `deliveryStatus` are blocked as well. GET/confirmation do not rewrite frozen facts, database status or digest; a fresh preview is required. The content-addressed mock ID checks internal fixture consistency, **not** source authentication or real provenance; neither it nor the preview-history sticky check is an authoritative production negative lookup or durable usage ledger. These fixtures must never authorize real join, sale or delivery. Production has no installed mock capability, and confirmation still returns `409 pending_write_fence` for a ready mock preview without remote calls. The post-join first measured and persisted zero evidence and production ledger/fence require separately reviewed implementation before any delivery grant.
