# Ticket 06: explicit Personal access, then read-only workspace discovery

The isolated Owner rebuild has **two separate** Owner-session + Origin + double-submit CSRF actions for a selected saved mother: `POST /api/owner/v1/mother-accounts/{accountId}/personal-session` for password+TOTP Personal session refresh, then `POST /api/owner/v1/mother-accounts/{accountId}/discovery` for read-only accounts/check discovery. GET on either path only reads saved state. Account import/save, GET, and selecting a mother never log in or discover. Even one returned space needs a further explicit target choice. The target choice is not an operational binding or permission grant.

`platform.PersonalSessionRefresher` is a typed, independently injected refresh boundary; the production control role uses `UnavailablePersonalRefresh`, so it cannot currently log in. The refresh result is validated before the Personal AT, session cookie names/values and device ID are AES-GCM encrypted with the deployment key ring and mother ID+credential revision as associated data. Secrets never appear in the Owner response. The credential generation, expiry, Owner session rotation and persisted refresh status are scoped to the selected mother. Missing/invalid saved password or 2FA is `missing_credentials`; invalid login is `invalid_login`; other refresh errors are `refresh_failed`; an unavailable adapter is `unavailable`. A failed refresh drops prior Personal session and visibility.

`platform.AccountsCheckDiscovery` implements the sourced, **read-only** fixed-host `GET https://chatgpt.com/backend-api/accounts/check/v4-2023-04-27?timezone_offset_min=-480` request with saved Bearer Personal AT, session cookies and device ID through an injected lease-owned HTTP client. It blocks redirects, caps responses, parses the accounts map strictly, filters personal/free/default, deduplicates by platform workspace ID and distinguishes successful empty from 401 `session_expired`, 403 `permission_denied`, and transport/parse/server `discovery_failed`. Mock transports cover these paths. The production control role instead injects `UnavailableDiscovery`; **no production remote traffic is enabled**. A future production adapter must acquire/release the existing egress lease, not use default HTTP or an arbitrary Owner-supplied URL.

`tsw_mother_personal_sessions` stores the Personal generation separately from the mother's source materials and from Workspace OAuth. `tsw_mother_workspace_visibility` stores each mother's observed access to the canonical workspace entity, not the operational `tsw_mother_workspace_bindings`. Credential rotation, expired Personal sessions, a failed/empty discovery or observations older than seven days invalidate displayed candidates. Visibility never proves management permission or subscription, seat, member or invitation facts; **do not use visibility to execute tasks**.

Reference evidence: `.scratch/team-rebuild/research/mother-workspace-discovery-readonly.md`, plus read-only `internal/thirtydayteam/session_login.go`, `workspace_visibility.go` and `internal/register/password_totp_login.go` in `/root/projects/kxj-gpt-reg-go-dev-next`. The target's existing OAuth login is workspace-selected and cannot be mistaken for the reference's confirmed Personal-only refresh. Implementing a production Personal refresh requires porting and validating its separate post-TOTP session confirmation and cookie/device generation under a platform egress lease, and a separate authorization to enable live calls. This commit is not a production login/discovery cutover.
