# Ticket 06: mother workspace discovery (local contract)

The isolated Owner rebuild uses `POST /api/owner/v1/mother-accounts/{accountId}/discovery` only after an explicit button press. It requires the existing Owner session, Origin and double-submit CSRF checks. `GET` reads the last saved result for the selected mother; neither account material saving nor GET contacts the platform. The UI requires a separate explicit choice even for one result and never treats visibility as management authorization.

The adapter boundary `platform.DiscoveryAdapter.VerifyAndDiscover` is injectable for simulated responses. The production control role supplies `UnavailableDiscovery`, which performs no network requests and returns `unavailable`. A missing/invalid 2FA is `missing_credentials`, an invalid login is `invalid_login`, a failure during discovery is `discovery_failed`, denied access is `permission_denied`, and an empty *successful* list is `empty`. Adapter errors and malformed/contradictory results cannot become a successful empty list. There is no user-supplied workspace ID discovery endpoint.

A discovered platform workspace ID is unique in `tsw_workspaces`. `tsw_mother_workspace_visibility` records the separate mother/workspace access observation, not `tsw_mother_workspace_bindings` (which is an operational relationship). Changing credentials, a new failed/empty run, or a result older than seven days removes visibility from the API. The new response contains no permission to manage, no subscription/seat/member/invitation facts, and no token or login secret. In particular **do not use visibility as permission to execute tasks**.

Read-only reference review (`/root/projects/.tsw-worktrees/research/mother-workspace-discovery-readonly.md`) found an accounts-check route requiring a saved Personal access token plus cookie/device context and potentially a distinct explicit password+TOTP refresh on 401. The target currently saves password/2FA, not this Personal session chain, and has no approved production login/refresh contract or live authorization. Enabling a real adapter requires that separately reviewed contract and credential/session handling; this slice must not be described as production remote discovery.
